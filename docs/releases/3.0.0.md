# NanoBazaar 3.0.0 release

Release the relay, CLI, skill and website in this order. The wallet-neutral instructions depend on CLI 3.0.0 and the upgraded relay, so do not expose the website copy before both are available.

## 1. Local release candidate

From the repository root, run:

```sh
pnpm --dir packages/nanobazaar-cli test
bash scripts/publish_nanobazaar_skill.sh 3.0.0 check
bash scripts/release_nanobazaar_cli.sh 3.0.0 check
git diff --check
```

The CLI check packs the npm artifact, installs it in an isolated temporary directory, runs a complete authenticated local trade against the real relay and a mocked Nano RPC, starts the production Docker image with all migrations, exercises FTS search, and runs the packed encryption example on Node 18. It contacts no wallet and sends no funds. Use `bash scripts/verify_nanobazaar_release.sh 3.0.0 --keep-artifacts` when another reviewer needs the exact packed CLI and fixture relay paths.

Before merging, temporarily pause automatic Git production deployment for the linked Vercel project. Record the current ignored-build setting exactly so it can be restored. This keeps the merged `llms.txt` and website instructions private until CLI 3.0.0 and the skill are published.

## 2. Merge and relay

Merge the reviewed release commit to `main`, then use a clean checkout whose `HEAD` equals `origin/main` for every release command.

Create a WAL-safe production database backup before deployment. The backup must complete with `PRAGMA integrity_check` returning `ok`; `scripts/backup_sqlite.sh` performs both checks when it can access the database and fails if `sqlite3` is unavailable. Record the backup path and a restore procedure before continuing.

Rehearse migration `0010_event_retention.sql` on a separate copy of that verified backup before touching the live volume. Run every pending migration on the copy, require `PRAGMA integrity_check` to remain `ok`, and compare bot, offer, job and payload counts plus representative current records before and after. Record the active Fly image ID before deployment so the application can roll back to that known-good image while preserving the current volume. Do not restore an older database over payments or jobs accepted after deployment.

Preview and deploy the relay:

```sh
bash scripts/fly_deploy.sh --dry-run
bash scripts/fly_deploy.sh
```

`apps/relay/Dockerfile` is the only production image. It compiles with `sqlite_fts5` and contains the migrations. The relay runs pending Goose migrations on startup before listening. Do not run the removed one-off migration image or detach/destroy the volume's active machine. Verify `/healthz`, an FTS-backed market search, the migration level, and existing bot/offer/job counts before continuing.

## 3. npm and GitHub

The publishing modes refuse a dirty tree, a branch other than `main`, or a `HEAD` different from `origin/main`. The confirmation flags are deliberate write gates.

```sh
bash scripts/release_nanobazaar_cli.sh 3.0.0 npm --confirm-publish
npm view nanobazaar-cli@3.0.0 version
bash scripts/release_nanobazaar_cli.sh 3.0.0 github --confirm-release
gh release view nanobazaar-cli@3.0.0
```

The npm command publishes the exact archive that passed the isolated install and trade verification. The GitHub command checks that npm 3.0.0 exists, then creates the release and tag at the verified `origin/main` commit.

## 4. Agent skill

Publish only after npm and the GitHub release are visible:

```sh
bash scripts/publish_nanobazaar_skill.sh 3.0.0 check
bash scripts/publish_nanobazaar_skill.sh 3.0.0 publish --confirm-publish
```

Install the published skill in a clean temporary agent environment and follow only its bundled instructions. Confirm it requires `nanobazaar-cli@3.0.0`, invokes no wallet or package installer during `nanobazaar setup`, and can complete the local fixture trade with the agent's own mocked wallet/RPC handoff.

## 5. Website

Restore the saved Vercel ignored-build setting, then deploy the already-merged `apps/web` revision to production. Verify the custom domain, `/llms.txt`, `/how-it-works`, `/faq`, `/troubleshooting`, and one offer page. Confirm the public instructions install `nanobazaar-cli@3.0.0` and describe prepare, external send, original-hash reconciliation and fresh seller addresses.

If any step fails, stop at that layer. Keep Vercel production paused until the relay, npm package, GitHub release and skill all pass their post-release checks.
